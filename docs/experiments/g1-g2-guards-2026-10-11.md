# G1/G2: Evidence Assessment and Claim Verification (2026-10-11)

Development set only: 28 questions (20 answerable, 4 insufficient-evidence, 4 clarification). Base configuration N2 (R3 retrieval + Decimal calculation). Not a held-out result.

## What Was Added

**G1, evidence assessment (code):**

- *Before generation*: flag an ambiguous period when the question has no year, or gives a bare year for a company whose recorded fiscal year end is not December (`documents.fiscal_year_end`, migration 005). Only evidence from the asked company is consulted. Flags are passed to the model as "System checks" requiring a clarification.
- *After generation*: unless the question asks for a segment, parent-only, or pro forma view, reject figures cited from parent-company-only (Schedule I) or pro forma sources, and figures that conflict with a consolidated statement row for the same label and year.
- The model also lists every stated figure (`facts`) with value as printed, label, unit, period, and evidence ID.

**G2, claim verification (code), on top of G1:**

- Each listed figure must appear in its cited excerpt on a row whose label matches and in its period's column (table excerpts), or with its year (text excerpts).
- If the figure is found only in another retrieved excerpt, the citation is repaired; if it is found nowhere, the answer is withheld.
- Every number in the answer text must be a verified figure or the computed result; rounded or converted forms ("$89.0 billion") fail.

Prompt `g-v1-4b68f05e51b1` for both G1 and G2; G2 differs only in code.

## Development Process and Its Risk

The first G1 design inferred fiscal year ends from table headers and required consolidated tables for every figure. A diagnostic on the 28 questions, without LLM calls, showed it missed the Apple and Walmart cases, flagged three Berkshire questions wrongly, and would reject correct answers drawn from narrative or summary tables. It was replaced by recorded fiscal year ends and the narrower conflict rule. After the change the period checks flagged exactly dev-11, dev-20, and dev-28 and no other question.

The first G2 runs rejected many correct answers. Each cause was a verifier defect found by reading the rejections: string instead of numeric comparison of the computed result, a label-overlap ratio that penalized long paraphrases, years followed by "," or ")" read as amounts, and non-numeric placeholders treated as figures. All were fixed with tests. These fixes were made while looking at development results, so the final test set must confirm that G2 does not over-reject on new companies.

What changed per question:

- **dev-03** (Berkshire 2023 operating cash flow): N2 answered 7,611 from the parent-only Schedule I in every run. G1 and G2 withhold it in every run. Correct retrieval is still missing, so this moves from a wrong answer to a deferral.
- **dev-11** (no year): N2 asked for the period but, in one run, offered a pro forma 2022 figure as the provisional answer. G1/G2 reject the pro forma source and return `insufficient_evidence`, which also loses the correct clarification state. Blocking a wrong figure cost a correct question back.
- **dev-28** (Walmart "2025"): N2 answered fiscal 2025 in every run without asking; with the period check G1/G2 ask in every run, though the model still gives only the fiscal 2025 reading, not both.
- **Citations**: in one G2 run the verifier repaired 4 citations per run in which the model cited a neighbouring excerpt; the figure was right but the cited excerpt did not contain it.
- **dev-12** ("how much did Berkshire earn") remains: in one G2 run the model answered with a verified figure instead of asking which metric. Metric ambiguity has no code check.

## Interpretation

- G1 removes the wrong figure (dev-03 in every N2 run) and turns dev-28 into a clarification, at the cost of one more deferral (dev-03) and of dev-11's clarification state. Accuracy is unchanged because the removed answer was wrong.
- G2 adds a verified source for every stated figure and repairs mis-citations. Compared with G1 it made no further change to wrong figures (already zero); the dev-12 difference (asked in more G2 runs) comes from the model, not from verification, and is within run-to-run variation.
- Clarification remains weak: the state improves with the period checks, but the model often omits the provisional values, and metric ambiguity is not detected.
- Unsupported Answer Rate as defined in the plan needs claim-level human judgment; "wrong answers among answered responses" is the automated proxy used here.
